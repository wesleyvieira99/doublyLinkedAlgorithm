01 / A IDEIA

Uma lista feita de conexões.

Você não move os valores de lugar.
Você muda quem aponta para quem.

Um array permite acessar uma posição diretamente pelo índice. Em uma lista encadeada, cada elemento vive em um nó. Para chegar ao seguinte, você segue uma referência.

Na versão duplamente encadeada, o nó também conhece seu anterior. É por isso que conseguimos caminhar de head até tail e voltar.

A lista guarda só três campos principais: o primeiro nó, o último nó e a quantidade de elementos. Os demais nós são alcançados pelas conexões.

Referências, não cópias. previous e next apontam para outros objetos Node. Nos extremos, uma dessas referências é null.

PASSO 01
O nó é a peça. A lista organiza as peças.
Node<E> representa um único nó. DoublyLinkedList<T> guarda as entradas da estrutura. Os nomes E e T são parâmetros de tipo: podem representar Integer, String ou outro objeto.
private static class Node<E> {
    E data;
    Node<E> previous;
    Node<E> next;

    Node(E data) { this.data = data; }
}

private Node<T> head; // começa como null
private Node<T> tail; // começa como null
private int size;     // começa como 0
Por que private? Quem usa a lista não precisa mudar os nós diretamente. Por que static? Cada nó não precisa carregar uma referência implícita para a instância externa da lista.
Em Java, use DoublyLinkedList<Integer>, não DoublyLinkedList<int>. Generics recebem tipos de referência; o autoboxing converte valores como 10 em Integer.


PASSO 02
Inserir é conectar antes de atualizar a ponta.
Imagine [10, 20] e a chamada addLast(30). O nó 20 ainda é o último enquanto você prepara as conexões.
  1. Crie o nó 30, inicialmente sem vizinhos.
  2. Faça newNode.previous = tail. O 30 passa a conhecer o 20.
  3. Faça tail.next = newNode. O 20 passa a conhecer o 30.
  4. Atualize tail = newNode e incremente size.
Node<T> newNode = new Node<>(value);
newNode.previous = tail;

if (tail == null) {
    head = newNode; // lista vazia
} else {
    tail.next = newNode;
}

tail = newNode;
size++;
E no início? O raciocínio se espelha: newNode.next = head, depois head.previous = newNode, e por fim head = newNode. Na lista vazia, o novo nó vira as duas pontas.
Não atualize tail cedo demais. Se você perder a referência ao último nó antigo, poderá conectar o novo nó a ele mesmo.


PASSO 03
Remover é fazer os vizinhos se reencontrarem.
Em 10 ⇄ 20 ⇄ 30, remover 20 não exige copiar 30 para seu lugar. Você muda as referências de 10 e 30. O método privado unlink centraliza essa lógica.
Node<T> before = node.previous;
Node<T> after = node.next;

if (before == null) head = after;
else before.next = after;

if (after == null) tail = before;
else after.previous = before;
No meio
O anterior aponta para o seguinte. O seguinte volta para o anterior.
No início
Não há anterior. head muda para o seguinte, cujo previous vira null.
No final
Não há seguinte. tail muda para o anterior, cujo next vira null.
O único nó
Os dois vizinhos são null. Logo, head e tail ficam null.
Guarde o valor antes de limpar o nó, desconecte suas referências, reduza size e retorne o valor removido. Java cuida da coleta de objetos que deixam de ser alcançáveis; você não chama free.
Encontrar e remover são custos diferentes. unlink(node) é O(1), mas remove(value) pode percorrer a lista inteira antes de encontrar o nó: O(n).


PASSO 04
Um índice não é um atalho.
Para get(2), é preciso caminhar até o terceiro nó. Ter referências nos dois sentidos permite começar pela ponta mais próxima.
if (index < size / 2) {
    current = head;
    for (int i = 0; i < index; i++) {
        current = current.next;
    }
} else {
    current = tail;
    for (int i = size - 1; i > index; i--) {
        current = current.previous;
    }
}
Em [5, 10, 20, 30], buscar o índice 2 começa no último nó, índice 3, e volta uma vez. É menos trabalho, mas o pior caso continua O(n).
Antes de caminhar, rejeite índices negativos ou maiores ou iguais a size com IndexOutOfBoundsException.


PASSO 05
Quatro regras que mantêm tudo conectado.
  1. Se a lista está vazia, head == null, tail == null e size == 0.
  2. Se há elementos, head.previous == null e tail.next == null.
  3. Se a.next == b, então b.previous == a.
  4. O número de nós alcançáveis a partir de head deve ser igual a size.
Essas regras precisam valer ao terminar cada operação. Durante uma atualização passo a passo, uma direção pode já ter mudado e a outra ainda não. O laboratório mostra exatamente esses estados intermediários.
Teste a lista vazia, um único nó, remoções no início e no final, valores repetidos e um valor ausente. Percorrer para trás ajuda a revelar erros que a impressão normal não mostra.




04 / COMPLEXIDADE
Onde ela ganha. Onde ela custa.
As pontas são rápidas porque já temos suas referências. O meio exige uma caminhada.
OperaçãoPior casoO que acontece
addFirst / addLastO(1)Atualiza poucas referências.
getFirst / getLastO(1)Acessa head ou tail diretamente.
removeFirst / removeLastO(1)O nó já está localizado.
get(index)O(n)Percorre a partir da ponta mais próxima.
remove(value)O(n)Busca o valor e então desconecta o nó.
size / isEmptyO(1)Consulta o contador.
toString / toReverseStringO(n)Visita todos os nós.
n = quantidade de elementos. A análise assume custo constante para comparar e representar cada valor. A estrutura ocupa O(n) memória e guarda duas referências por nó, além do valor e do custo do próprio objeto.
Use o raciocínio de uma lista
Quando o acesso às pontas é central ou quando você já está em um nó e precisa alterar sua vizinhança. Esta implementação expõe inserção apenas nos extremos.
Compare com um ArrayList
Se você acessa frequentemente por índice, ArrayList oferece acesso O(1) e costuma ter melhor localidade de memória. “Encadeada” não significa “mais rápida em tudo”.

Por que usar Objects.equals em vez de ==?
== compara a identidade de objetos. Para remover pelo conteúdo, usamos igualdade de valores. Objects.equals(a, b) usa equals com tratamento seguro de null. Para classes próprias, implemente equals conforme o significado de igualdade no seu domínio.
Posso guardar null ou valores repetidos?
Sim. Esta implementação permite ambos. remove(value) remove apenas a primeira ocorrência. Consultar ou remover uma ponta vazia lança NoSuchElementException; um null retornado de uma lista não vazia pode ser um valor realmente armazenado.
Por que limpar as referências do nó removido?
As conexões da lista já foram corrigidas. Limpar previous, next e data evita retenções desnecessárias caso ainda exista alguma referência ao nó. Nesta implementação os nós são privados; sem referências alcançáveis, o coletor de lixo pode recuperar sua memória.
É a mesma coisa que java.util.LinkedList?
A ideia de encadeamento duplo é semelhante, mas esta é uma implementação didática. Ela não implementa as interfaces List ou Deque, nem iteradores, nem todas as operações e contratos da biblioteca padrão. Também não é sincronizada para uso concorrente.
